Flowchart KampusPay STTP - Web & Android (Detail)

Satu aplikasi: Web (Admin, Kasir) + Android (Mahasiswa). Alur gabungan termasuk notifikasi, email, dan kode pembayaran.

1. Alur Login & Penentuan Role/Platform
flowchart TD Start([Mulai]) Start --> A[Halaman Login] A --> B[/Input Username dan Password/] B --> C{Validasi} C -->|Tidak| A C -->|Ya| D{Cek Role} D -->|Admin| E[Dashboard Admin - Web] D -->|Kasir| F[Dashboard Kasir - Web] D -->|Mahasiswa| G[Dashboard Mahasiswa - Web/Android]
2. Notifikasi ke Mahasiswa - Saat Tagihan Dibuat (Admin/Kasir)
flowchart LR subgraph Web A1[Admin/Kasir Buat Tagihan] end A1 --> DB[(Database)] DB --> N1[Kirim Email] DB --> N2[Notifikasi Database] N1 --> E1[Email ke Inbox Mahasiswa] E1 --> E2[Isi: Detail tagihan, Jumlah, Kode Pembayaran, Link Bayar] N2 --> D1[Simpan di tabel notifications] D1 --> D2[Muncul di Dashboard Mahasiswa - Web/Android]
3. Notifikasi ke Kasir - Saat Mahasiswa Pilih Aktivasi
flowchart LR subgraph Android M1[Mahasiswa Pilih Aktivasi Aktif/BSS] end M1 --> DB2[(Database)] DB2 --> N3[AktivasiStatusChanged] N3 --> K1[Notifikasi ke Semua Kasir] K1 --> K2[Bell Icon di Dashboard Web Kasir] K2 --> K3[Isi: Nama mahasiswa, NPM, semester, status]
4. Kode Pembayaran - Flow untuk Mahasiswa (Android/Web)
flowchart TD T1[Admin/Kasir Buat Tagihan] T1 --> Gen[Generate Kode Pembayaran] Gen --> Save[(Simpan ke Database)] Save --> P1[Email ke Mahasiswa] Save --> P2[API Response ke App] P1 --> M1[Mahasiswa terima email] M1 --> M2[Kode ada di email + link Bayar] P2 --> M3[Mahasiswa lihat di App Android/Web] M3 --> M4[Kode tampil di detail tagihan] M2 --> Pay[Bayar di Kasir] M4 --> Pay Pay --> Kasir[Kasir input kode untuk proses bayar tunai]
5. Proses Pembayaran Mahasiswa - Detail (Web & Android)
flowchart TD D[Dashboard Mahasiswa] D --> N{Ada Notifikasi?} N -->|Ya| N1[Email + In-App Notification] N1 --> L[Klik Link / Buka App] N -->|Tidak| L L --> Tag[Lihat Tagihan] Tag --> Metode[Pilih Metode Pembayaran] Metode --> T1[Tunai] Metode --> T2[Transfer] Metode --> T3[Cicilan] T1 --> S1[Status: Menunggu Bayar di Kasir] S1 --> K1[Datang ke kasir dengan Kode Pembayaran] T2 --> U1[Upload Bukti Transfer] T3 --> U2[Input Jumlah + Upload Bukti] U1 --> V1[Menunggu Verifikasi Kasir - Web] U2 --> V1 V1 --> V2{Kasir Verifikasi} V2 -->|Setujui| DB[(Database)] V2 -->|Tolak| Tolak[Status Ditolak]
6. Ringkasan Satu Aplikasi - Web & Android
flowchart TB subgraph Web["Platform Web"] subgraph Admin["Admin"] A1[Mahasiswa] A2[Tarif] A3[Tagihan] A4[Pembayaran] A5[Laporan] A6[Pengaturan] A7[User] end subgraph Kasir["Kasir"] K1[Proses Bayar Tunai] K2[Tagihan] K3[Verifikasi Transfer] K4[Aktivasi] K5[Riwayat] K6[Laporan] K7[Notifikasi Aktivasi] end end subgraph Android["Platform Android"] subgraph Mahasiswa["Mahasiswa"] M1[Pembayaran] M2[Riwayat] M3[Laporan] M4[Kwitansi] M5[Aktivasi] M6[Notifikasi Tagihan] end end Admin --> DB[(Database)] Kasir --> DB Mahasiswa --> API[API] API --> DB
Ringkasan: Web untuk Admin & Kasir. Android untuk Mahasiswa (via API). Satu database. Notifikasi: (1) Tagihan baru → Email + in-app ke Mahasiswa, (2) Aktivasi → In-app ke Kasir di Web. Kode Pembayaran = voucher/referensi yang dikirim ke Mahasiswa via email & tampil di app.
